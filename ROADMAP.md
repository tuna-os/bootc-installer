# bootc-installer Roadmap

**Last updated**: 2026-09-24 | **Maintainer**: tuna-os (hanthor)

---

## Mission

bootc-installer is the org's install front door: the monorepo for every
TunaOS / Bluefin installer frontend. Five frontends (GNOME at the root; KDE,
COSMIC, Niri and XFCE under `frontends/`) render one shared screen contract
and write one shared recipe for the `fisherman` Go backend, which executes the
9-step pipeline (partition → format → LUKS → mount → `bootc install` →
post-install → Windows migration → finalize) on both the systemd-boot/UKI stack
(Dakota) and the GRUB2 stack (Bluefin, Bluefin-LTS, Bazzite).

**The repository changed shape on 2026-09-17.** Four separate frontend
repositories (`tuna-installer-kde|cosmic|niri|xfce`) were imported with
`git subtree add` and frozen; they no longer resolve on GitHub. What used to
be a cross-repo parity goal is now an in-repo property, measured in CI. The
record of the move, and every issue and PR it carried over, is

**Theme was**: stable, token-safe install UX. What actually happened was
larger: the monorepo consolidation.

| Goal | Tracking | Outcome |
|---|---|---|

### 2026 Q4 (October–December)

**Theme**: five installers that ship, from one repository.

- Flatpak remote carries all five frontends, published only by promotion
  (#100, #107); the docs smoke test stays green for a full month.
- Signed Flatpak releases and SBOM aligned with the org supply-chain work
  (tunaos#1187).
- LUKS-first and dual-boot scenarios validated on the RHEL track
  (tunaos#1123).
- Browser rendering for all five frontends, so every frontend can be tested
  and demonstrated without a desktop session (#102–#105).
- `shared/` is the only copy of the recipe schema and parity report.
- Per-frontend roadmaps either folded into this file or rewritten for the
  monorepo.
- Windows-migration QA matrix shipped; recovery and rollback path documented.

## How to contribute

See [CONTRIBUTING.md](CONTRIBUTING.md) and [AGENTS.md](AGENTS.md). PRs target
`dev`; `prod` is only ever written by promotion. Good entry points: the
non-GTK browser harnesses (#103, #104), folding the vendored KDE and COSMIC
copies into `shared/`, and the Windows-migration QA fixtures.

## Roadmap governance

Updated after major milestones or quarterly. Propose changes via PR to this
file with an issue reference; every status claim should point at a workflow,
a document or an issue that a reader can check.
